# Embedding Pulse in PowerPoint (content add-in)

Embeds the Pulse projector/poll view **live in a PowerPoint slide** – like a
Mentimeter slide. No Office Store needed; the add-in is loaded by **sideloading**.

## How it works

The Office manifest is **generated by your own Nextcloud**, not shipped as a
file: an Office manifest has no variables, and `<AppDomain>` and
`<SourceLocation>` have to be absolute URLs. So every instance serves its own,
ready-to-use manifest at `/apps/pulse/addin/manifest.xml`.

The manifest points to the hosted shell `/apps/pulse/embed`. The shell loads
`office.js`, asks **once** for the six-character room code (stored in the
document settings of the `.pptx`) and then frames `/apps/pulse/screen/{code}`
from the same origin. When the moderator moves on to the next question in the
deck, the slide updates by itself (Pulse's own state polling).

## Requirements

- **PowerPoint for Windows** 2016+ or Microsoft 365 (desktop). LibreOffice Impress
  and PowerPoint on the web cannot run content add-ins.
- The presentation laptop can reach the Nextcloud address in the manifest → **LAN,
  VPN or public**.
- **Internet** for `office.js` (Microsoft CDN) — the add-in wrapper needs it; the
  poll content comes from the Nextcloud instance.
- The web server/proxy has to drop `X-Frame-Options` for two paths (see below).
  Pulse checks this itself and reports it under **Administration → Overview**.

## Setup (once)

### 0. Download the manifest from your own instance

In Pulse, open a room → the deck's overflow menu → **"PowerPoint add-in"**.
Or directly: `https://YOUR-INSTANCE/apps/pulse/addin/manifest.xml`.

The file is fully filled in — it carries exactly the address it was downloaded
from. If you use different names internally and publicly, download it from the
address that the **presentation laptop** can reach.

Do not edit it by hand. If the instance's address changes, download it again;
the add-in ID (`<Id>`) stays the same, so PowerPoint recognises it as the same
add-in.

### 1a. For a single person: shared folder

1. Create a folder, e.g. `C:\PulseAddin`.
2. Copy the downloaded `pulse-addin.xml` into it.
3. Share the folder: right-click → **Properties → Sharing → Share…**
   (or **Advanced Sharing**), share name e.g. `PulseAddin`.
   The result is a UNC path like `\\YOUR-PC\PulseAddin`.
4. PowerPoint → **File → Options → Trust Center →
   Trust Center Settings… → Trusted Add-in Catalogs**.
5. Enter the UNC path `\\YOUR-PC\PulseAddin` as the **Catalog Url** →
   **Add catalog**.
6. Tick **"Show in Menu"** for it in the list → **OK**.
7. **Restart PowerPoint.**

This is the route without a Microsoft account — but it has to be done once per
computer.

### 1b. For an organisation: central deployment

With Microsoft 365 it can be done once for everybody: **Microsoft 365 admin
center → Settings → Integrated apps → Upload custom apps**, upload the same
`pulse-addin.xml` there and assign it to people or groups. The add-in then
appears in PowerPoint by itself, without a catalog and without a Trust Center
entry on every device.

### 2. Insert the add-in
1. **Insert → My Add-ins** → for the folder route, additionally
   **▾ → Shared Folder**.
2. Choose **Pulse live poll** (in a German Office: "Pulse Live-Umfrage") →
   **Add/Insert**.
3. The add-in appears on the slide: **type in the room code → Show**.
   (Create the room in Pulse beforehand to get a code.)
4. **Slide show (F5):** the poll runs live in the slide.
   The audience votes on their phones as usual, via QR code or `/s/CODE`.

To change the code later: hover over the add-in → top bar →
**"Change code"**.

## Troubleshooting

| Symptom | Cause / fix |
|---|---|
| Add-in does not show up under "My Add-ins" | The catalog URL has to be a **UNC path** (`\\…`), not `C:\…`; is "Show in Menu" ticked? PowerPoint restarted? |
| Box stays white/empty | `X-Frame-Options` is still there (look at the check under **Administration → Overview**). Otherwise: is the laptop on the **LAN/VPN**? Is there **internet** for `office.js`? Cross-check: open the `<SourceLocation>` address from the manifest with `?code=YOURCODE` in the laptop's browser. |
| Add-in shows a foreign/old address | The manifest comes from another instance or from before an address change — download it again (step 0). |
| "Add-in error" / does not load | The laptop has to trust the instance's certificate (Let's Encrypt is enough). Check whether the shell loads in the laptop's browser. |
| Wrong/old code is stuck | Use **"Change code"** in the hover bar. The code is stored in the `.pptx`. |

## Web server requirement: `X-Frame-Options` has to go

This affects **every** Nextcloud instance, not just one particular setup.
Nextcloud sends the header from its own code, in two places:

```
.htaccess:35     Header always set X-Frame-Options "SAMEORIGIN"
lib/base.php     header('X-Frame-Options: SAMEORIGIN')   # fallback without mod_headers
```

`always set` **cannot** be overridden from PHP — an app has no way to get rid of
the header. It has to be removed at the web server or proxy level, and only for
the two display paths:

- `/apps/pulse/screen/…` — projector/audience view (read-only)
- `/apps/pulse/embed` — the add-in shell

**Both also with `/index.php` in front.** Without `htaccess.IgnoreFrontController`
Nextcloud builds its addresses as `/index.php/apps/pulse/embed`, and a rule that
only knows the short form never applies. The snippets below cover both. (This is
exactly how it once failed in practice: the same page came back without the
header under the short address and with it under the long one.)

The voting page `/s/{code}` deliberately stays blocked. The second framing
barrier, CSP `frame-ancestors`, is handled by the app itself
(`PublicController::screen`/`embed`).

**Traefik** — a ready-made file is here under [`traefik/`](traefik/); on the
server it goes into the file provider's directory. Adjust host, `service` and
`certResolver` (marked in the file).

**Apache** (in the vhost configuration, not in Nextcloud's `.htaccess` — that
one is overwritten on updates):

```apache
<LocationMatch "^(/index\.php)?/apps/pulse/(screen/|embed)">
    Header always unset X-Frame-Options
</LocationMatch>
```

**nginx** (in the `location` block that passes on to PHP):

```nginx
location ~ ^(/index\.php)?/apps/pulse/(screen/|embed) {
    proxy_hide_header X-Frame-Options;   # reverse proxy in front
    # or with php-fpm directly: fastcgi_hide_header X-Frame-Options;
    ...
}
```

Check — the header must **not** show up:

```sh
curl -sI https://YOUR-INSTANCE/apps/pulse/embed            | grep -i x-frame-options
curl -sI https://YOUR-INSTANCE/index.php/apps/pulse/embed  | grep -i x-frame-options
```

Pulse does the same on its own: the setup check **"Pulse: embedding in
PowerPoint"** (Administration → Overview) fetches the embed page under every
address the server can reach itself on — and reports it separately when the
rule applies for the internal name but is missing for the public one. Without
that check the embedding breaks **silently**: the projector page keeps loading
in the browser, while in PowerPoint the box stays empty.

**Hosted/managed Nextcloud** without access to the web server or proxy: the
embed does not work there. The way to go is then the projector view in a second
window instead of in the slide — it needs neither the add-in nor a header rule
nor Microsoft.
